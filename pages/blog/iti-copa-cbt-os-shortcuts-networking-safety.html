ITI COPA CBT: OS Basics, Shortcuts, Networking & Lab Safety Checklist

A practical, original revision map for COPA trainees — operating-system ideas, keyboard shortcuts that trip MCQs, networking & internet basics, and computer-lab safety for AITT CBT.

26 Sep 2026 · COPA · ~8 min read

COPA theory CBT rewards clear definitions more than memorising menu screenshots. If you can explain why RAM differs from storage, or what a phishing link tries to do, twisted options become easier. This checklist is original study advice — not a copy of any NIMI book or coaching PDF. Confirm your batch syllabus on Bharat Skills.

Unofficial guide. Always verify exam pattern and dates on DGT / NCVT MIS / Skill India Digital. We do not host copyrighted NIMI PDFs.

1. OS basics flash cards (memorise these)

  • Program vs process: a program is the stored instructions on disk; a process is that program while it is running in memory (with its own resources).
  • File system purpose: organises how files and folders are named, stored, and found on a drive — without it, storage is just raw bytes.
  • RAM vs storage: RAM is fast, temporary working memory (cleared on power-off); HDD/SSD storage keeps files after shutdown. More RAM helps multitasking; it does not permanently “save” documents by itself.
  • What a reboot does: restarts the OS, clears many temporary states and stuck processes, and reloads drivers/services from a clean start — it is not a substitute for saving your work first.
  • Admin vs standard user: an administrator can install software, change system settings, and manage other accounts; a standard user has limited rights — safer for daily lab work because malware/mistakes do less damage.
  • OS role (idea): manages hardware, runs applications, and provides a user interface — Windows, Linux distributions, and macOS are different OS products with the same core jobs.

Exam tip: if an option says “RAM permanently stores your Word file after shutdown,” reject it. Saved files live on storage; RAM is volatile.

2. Keyboard shortcuts & file concepts that trip MCQs

Learn the action first, then the keys — papers love mixing similar shortcuts:

  • Ctrl+C / Ctrl+X / Ctrl+V: copy / cut / paste. Cut removes from the source after paste (or marks for move); copy leaves the original.
  • Ctrl+Z / Ctrl+S / Ctrl+A / Ctrl+P: undo / save / select all / print. Save early and often — reboot will not restore unsaved edits.
  • Alt+Tab: switch between open applications/windows — useful under timed CBT practice on a PC.
  • Ctrl+Alt+Del (purpose idea): secure attention sequence on many Windows PCs — opens options for lock, switch user, Task Manager, or sign out (exact screen varies by version/policy). Know the purpose, not every button label.
  • Recycle Bin vs Shift+Delete: normal Delete usually sends to Recycle Bin (recoverable until emptied); Shift+Delete typically bypasses the Bin (harder/impossible to undo casually) — use with care in labs.
  • Extensions: .docx ≈ Word document, .xlsx ≈ Excel workbook, .pdf ≈ portable document. The extension hints at the default app; renaming the extension does not magically convert the real file format.

Trap: “Ctrl+V means permanently delete” is wrong. Paste ≠ delete.

3. Networking & internet basics

  • LAN vs WAN: LAN (local area network) covers a small area — lab, office, home. WAN (wide area network) spans cities/countries; the public Internet is the largest WAN example students meet.
  • IP address idea: a numeric (or IPv6) label that helps identify a device on a network so packets can be delivered — like a postal address for data, not the same as a website name.
  • Browser vs search engine: a browser (Chrome, Edge, Firefox…) is the program that displays web pages; a search engine (Google, Bing…) finds pages from keywords. You use a browser to open a search engine.
  • URL parts (idea): protocol (https://), domain name, and path/query. https adds transport encryption — helpful, but not a full guarantee the site is trustworthy.
  • Phishing caution: fake emails/sites that imitate banks, colleges, or “account verify” pages to steal passwords or OTPs. Check the real domain, don’t click panic links, and never share lab/exam passwords on unknown forms.

Exam tip: if an option says “a search engine is hardware that stores websites,” reject it. Search engines are services; browsers are client software.

4. Lab safety & ergonomics checklist (high-yield)

  • Sit with neutral posture: screen roughly at eye level, back supported, wrists straight — long exam/practice sessions punish slouching
  • Route cables so aisles stay clear — trip hazards injure more people than “dramatic” electrical faults in many labs
  • Know surge protector / UPS awareness: UPS gives short backup and cleaner shutdown time; it is not infinite battery for gaming all night
  • No food or open drinks near keyboards and CPUs — spills kill ports and cause downtime before exams
  • Password hygiene for lab accounts: unique passwords, don’t share logins, lock the screen when you leave (Win+L idea on many PCs)
  • Report damaged cables, overheating smell, or cracked screens instead of “making do” — tell the instructor

5. Two exemplar MCQs (original)

Practice / exemplar questions — not from any leaked paper. Written for learning only.

Q1. Which statement correctly describes the difference between RAM and HDD/SSD storage?
A. RAM permanently keeps files after the PC is powered off; storage is only temporary
B. RAM is fast volatile working memory; storage keeps files after shutdown
C. Both are identical and only differ by brand name
D. Storage is used only for printing
Answer: B — RAM is volatile working memory; permanent files live on storage.
Q2. A trainee receives an email that looks like their bank and asks them to click a link and enter the password “to avoid account closure.” The safest study answer is:
A. Click immediately and share the OTP as requested
B. Treat it as possible phishing — verify via official channels; do not enter credentials on suspicious links
C. Forward the password to classmates for “group safety”
D. Disable the lab UPS and ignore the mail
Answer: B — Phishing tries to steal credentials; verify officially and never submit passwords on panic links.

6. One-week COPA theory sprint

  • Day 1–2: OS concepts — process, file system, RAM vs storage, user accounts
  • Day 3: Shortcuts, extensions, Recycle Bin vs permanent delete
  • Day 4: LAN/WAN, IP idea, browser vs search engine, URL & https idea
  • Day 5: Word / Excel / PowerPoint identification tasks your syllabus emphasises
  • Day 6: Lab safety, password hygiene, phishing + Employability Skills
  • Day 7: Timed COPA mini-mock + error-notebook repair only
